# PKL Studio — Devine Bachelor Thesis Blog

Digital process archive by Phoebe, Kiara and Lenie for our bachelor thesis as
Devine students at Howest Kortrijk. We use this blog to document our UX research,
design process and development work for lecturers, jury members and anyone
interested in our project.

## Lokaal starten

Installeer de dependencies en start daarna de ontwikkelserver:

```bash
npm install
npm run dev
```

Open vervolgens de URL die Vite toont, meestal `http://localhost:5173/`.

Voor een productiebuild:

```bash
npm run build
```

## Teamomgeving

De publieke website is alleen-lezen. Teamleden voegen posts toe via `team.html`.
De teamomgeving gebruikt Supabase Auth en een centrale `posts`-tabel, zodat nieuwe
posts voor alle bezoekers zichtbaar zijn.

1. Maak een gratis project aan op [Supabase](https://supabase.com).
2. Open in Supabase **SQL Editor** en voer dit uit:

```sql
create table public.posts (
  id bigint generated by default as identity primary key,
  category text[] not null default array['ux'],
  title text not null check (char_length(title) between 1 and 80),
  body text not null,
  date timestamptz not null default now()
);

alter table public.posts enable row level security;

create policy "Anyone can read posts"
on public.posts for select
to anon, authenticated
using (true);

create policy "Team can add posts"
on public.posts for insert
to authenticated
with check (true);

create policy "Team can delete posts"
on public.posts for delete
to authenticated
using (true);
```

3. Maak in Supabase voor elk teamlid een account via **Authentication → Users**.
4. Vul de project-URL en de `anon` key in bovenaan `js/data.js`.
5. Publiceer opnieuw naar GitHub Pages. Bezoekers gebruiken de gewone site;
   teamleden openen `team.html`.

### Profielen en conclusies

Voer na het aanmaken van de tabel deze eenmalige migratie uit. De auteur wordt
automatisch gekoppeld aan het ingelogde Supabase-account; teamleden hoeven bij
een post geen naam of foto meer te kiezen:

```sql
alter table public.posts
  add column if not exists author_id uuid references auth.users(id),
  add column if not exists conclusion text,
  add column if not exists ai_usage text;

create table if not exists public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  display_name text not null,
  avatar_url text
);

alter table public.profiles enable row level security;

create policy "Anyone can read profiles"
on public.profiles for select
to anon, authenticated
using (true);

create policy "Users manage their own profile"
on public.profiles for all
to authenticated
using (auth.uid() = id)
with check (auth.uid() = id);

insert into storage.buckets (id, name, public)
values ('avatars', 'avatars', true)
on conflict (id) do nothing;

create policy "Anyone can view avatars"
on storage.objects for select
to anon, authenticated
using (bucket_id = 'avatars');

create policy "Users upload their own avatar"
on storage.objects for insert
to authenticated
with check (bucket_id = 'avatars' and (storage.foldername(name))[1] = auth.uid()::text);

create policy "Users update their own avatar"
on storage.objects for update
to authenticated
using (bucket_id = 'avatars' and (storage.foldername(name))[1] = auth.uid()::text)
with check (bucket_id = 'avatars' and (storage.foldername(name))[1] = auth.uid()::text);
```

Als Supabase nog steeds een RLS-fout geeft bij het uploaden, vervang dan de
twee avatar policies door deze variant:

```sql
drop policy if exists "Users upload their own avatar" on storage.objects;
drop policy if exists "Users update their own avatar" on storage.objects;

create policy "Users upload their own avatar"
on storage.objects for insert
to authenticated
with check (
  bucket_id = 'avatars'
  and name like auth.uid()::text || '/%'
);

create policy "Users update their own avatar"
on storage.objects for update
to authenticated
using (
  bucket_id = 'avatars'
  and name like auth.uid()::text || '/%'
)
with check (
  bucket_id = 'avatars'
  and name like auth.uid()::text || '/%'
);
```

Een teamlid vult in `team.html` de profielgegevens één keer in via **YOUR TEAM
PROFILE** en uploadt daar een foto. Daarna worden naam en foto automatisch bij
iedere nieuwe post gebruikt. Voer ook deze policy uit als je de bestaande
policies al eerder hebt aangemaakt:

```sql
create policy "Team can add posts with own author"
on public.posts for insert
to authenticated
with check (auth.uid() = author_id);

create policy "Team can update own posts"
on public.posts for update
to authenticated
using (auth.uid() = author_id)
with check (auth.uid() = author_id);

drop policy if exists "Team can add posts" on public.posts;
```

### Gedeelde teamchat

De teamomgeving bevat ook een gedeelde chatruimte. Voer deze SQL uit in
Supabase om berichten op te slaan en alleen ingelogde teamleden toegang te
geven:

```sql
create table if not exists public.team_messages (
  id bigint generated by default as identity primary key,
  message text not null check (char_length(message) between 1 and 1000),
  author_id uuid not null references auth.users(id) on delete cascade,
  created_at timestamptz not null default now()
);

alter table public.team_messages enable row level security;

alter publication supabase_realtime add table public.team_messages;

create policy "Team can read chat messages"
on public.team_messages for select
to authenticated
using (true);

create policy "Team can send chat messages"
on public.team_messages for insert
to authenticated
with check (auth.uid() = author_id);

create policy "Users update their own chat messages"
on public.team_messages for update
to authenticated
using (auth.uid() = author_id)
with check (auth.uid() = author_id);

create policy "Users delete their own chat messages"
on public.team_messages for delete
to authenticated
using (auth.uid() = author_id)
```

### Team drafts

Iedere teamgenoot kan meerdere eigen drafts bewaren. Drafts blijven bestaan wanneer
een andere note gepubliceerd wordt en worden alleen verwijderd wanneer je ze zelf
verwijdert.

```sql
create table if not exists public.team_drafts (
  id bigint generated by default as identity primary key,
  author_id uuid not null references auth.users(id) on delete cascade,
  category text[] not null default array['ux'],
  title text not null default '',
  body text not null default '',
  conclusion text,
  ai_usage text,
  updated_at timestamptz not null default now()
);

alter table public.team_drafts enable row level security;

create policy "Users manage their own draft"
on public.team_drafts for all
to authenticated
using (auth.uid() = author_id)
with check (auth.uid() = author_id);

-- Run this when upgrading an existing team_drafts table:
alter table public.team_drafts
drop constraint if exists team_drafts_author_id_key;

-- Run this when upgrading existing posts and drafts to multiple thesis pillars:
alter table public.posts
  drop constraint if exists posts_category_check;
alter table public.posts
  alter column category type text[] using array[category],
  alter column category set default array['ux'];
alter table public.team_drafts
  drop constraint if exists team_drafts_category_check;
alter table public.team_drafts
  alter column category type text[] using array[category],
  alter column category set default array['ux'];
```
